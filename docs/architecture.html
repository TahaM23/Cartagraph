How Cartograph works

Paste a public GitHub repository, and Cartograph parses it into a map of files and imports. Every box and line comes from parsing the code. The model only labels and explains; it never decides what is connected to what.

4. The map itself

The map page reads the stored files, edges and routes once, through the user's client. Everything after that happens in the browser as pure functions over the edge list: folding folders into about two dozen boxes, blast radius and dependency chains two levels out, and the insights panel. None of it needs a network request, so it all appears instantly.

5. Evals

These are scripts you run from the terminal, not part of the app. They read the same traces from LangSmith:

  • pnpm eval:paths runs the invented-path check over recent real explanations. This is set membership, with no model involved.
  • pnpm eval:roles hides the role on files a convention already identified, asks the model for it, and scores the answers against the known roles.
  • pnpm eval:prompts runs the current and the previous explanation prompt as two experiments, with a model as judge.
